## MVP de CMS editorial basado en Git
- [x] Construir el espacio editorial conectado a un repositorio de contenido en GitHub, con una identidad visual de “mesa de edición” sobria y técnica — tipografía sans legible, tonos papel/pizarra con acentos ámbar, composición densa pero clara y un mapa visual del estado repositorio → validación → preview—, incluyendo selector de rama, estado de sincronización, búsqueda, filtros y biblioteca de documentos.
- [x] Implementar esquemas declarativos y gestión completa de documentos autocontenidos: crear, editar mediante formularios generados por esquema, guardar borradores, duplicar, archivar y cambiar estado; incluir tipos configurables, identidad estable, metadatos, cuerpo Markdown, localización y relaciones por identificador.
- [x] Añadir validación estructural, editorial y referencial, workflow draft/review/approved/published/archived y una vista de preview que distinga contenido almacenado, validado y publicado, bloqueando el avance cuando existan errores publicables.
- [x] Implementar el centro de operaciones Git con cambios pendientes, diff por documento, commits trazables, pull/push, detección de cambios externos y conflictos, historial por documento y restauración controlada de versiones.
